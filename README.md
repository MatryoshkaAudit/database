# MatryoshkaAudit / Database & Polyglot Persistence Architecture

Архитектурный пакет хранения данных платформы **MatryoshkaAudit**. В системе реализован гибридный шаблон **Polyglot Persistence** (OLTP + OLAP), разделяющий операционные транзакции и высокоскоростную аналитику временных рядов.

---

## 🏛️ Архитектура баз данных (Polyglot Persistence)

```
                       ┌────────────────────────────────────────────────────────┐
                       │           ПЛАТФОРМА «МАТРЁШКА.АУДИТ»                   │
                       └────────────────────────────────────────────────────────┘
                                   │                                │
            [Транзакционный контур OLTP]             [Аналитический контур OLAP]
                                   │                                │
                    ┌──────────────▼─────────────┐     ┌────────────▼──────────────┐
                    │      PostgreSQL 16         │     │       ClickHouse 24       │
                    │   (ACID, Реляционные графы)│     │  (ReplacingMergeTree, VaR)│
                    └────────────────────────────┘     └───────────────────────────┘
                                   ▲                                ▲
                                   │                                │
                    ┌──────────────┴─────────────┐     ┌────────────┴──────────────┐
                    │ enterprise-service (8001)  │     │  analytics-service (8003) │
                    │ regulator-service  (8002)  │     │ (Analytics Gateway/Engine)│
                    └────────────────────────────┘     └───────────────────────────┘
```

### 1. PostgreSQL 16 (Операционный транзакционный слой — OLTP)
Отвечает за целостность бизнес-сущностей, строгие связи внешних ключей (Foreign Keys) и каскадные операции:
- `Product`: реестр промышленной продукции (харвестеры, станки ЧПУ, комбайны, тракторы).
- `Component`: иерархический граф конструкторской спецификации BOM (Tier 1-3), метрики CFI (O-Ring).
- `Supplier`: контрагенты, цепочки владения, юрисдикции и транзитные хабы.
- `Analog`: база верифицированных отечественных аналогов, стоимость редизайна и сроки внедрения.
- `Certificate`: цифровые государственные заключения Минпромторга РФ с хэш-подписью SHA-256.
- `PolicyRule`: нормативные отраслевые пороги баллов по ПП РФ № 719 / № 878.
- `CountryRisk`: матрица геополитических рисков и санкционных ограничений.
- `User`: ролевая модель доступа RBAC (Инженер предприятия / Инспектор Минпромторга).

### 2. ClickHouse 24 (Аналитический высокоскоростной слой — OLAP)
Отвечает за поколоночное хранение, неизменяемость истории и стохастические вычисления:
- `audit_ledger_events` (`ReplacingMergeTree`): неизменяемый криптографически подписанный распределенный реестр регуляторных решений, исключающий фальсификацию задним числом.
- `monte_carlo_shock_runs` (`MergeTree`): сжатое хранение миллионов стохастических итераций Монте-Карло для оценки Supply Chain VaR.

## ❓ Почему микросервисы не лезут напрямую в ClickHouse?

В соответствии с каноническим стандартом микросервисной архитектуры (**Database-per-Service Pattern** и **Analytics Gateway**):
1. **Изоляция доменных границ**: Сервисы `enterprise-service` и `regulator-service` не должны иметь жесткой связности со схемой ClickHouse и драйверами `clickhouse-connect`.
2. **Единый контур валидации и криптоподписи**: Все аналитические события проходят через Pydantic v2 валидацию и расчет SHA-256 в `analytics-service`.
3. **Безопасность и масштабируемость**: Пул подключений к ClickHouse изолирован в одном высокопроизводительном асинхронном микросервисе, не блокируя транзакционный пул PostgreSQL.

## 🚀 Быстрый запуск и инициализация

```bash
# 1. Запуск инфраструктуры (PostgreSQL, ClickHouse, Redis)
docker compose up -d matryoshka_postgres matryoshka_clickhouse matryoshka_redis

# 2. Установка пакета в виртуальное окружение
pip install -e .

# 3. Инициализация и сидирование PostgreSQL эталонными изделиями (Харвестер ЛХ-4, Станкомаш)
python -m matryoshka_db.seed_data
```
